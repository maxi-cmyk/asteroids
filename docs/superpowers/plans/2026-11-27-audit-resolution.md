## Global Constraints

- Branch workflow: work on `dev` (staging); `main` is deployed. `engine/` is shared by web and ESP32; `firmware/` is ESP32-only. Engine changes must keep `sh engine/tests/run_host.sh` and the WASM builds green.
- Every commit must pass `cd web && npm run check` (Prettier, ESLint, all three WASM builds, tests).
- Never run `UPDATE_GOLDEN=1` to make a gate green. A golden file changes only with a written justification in the commit message.
- No hardware-dependent number (I2C clock, frame budget, calibration threshold) is invented. Items needing a bench measurement stay marked "hardware-gated".
- CI runtime is Node 22; local is Node 26.12. Final verification runs under both if Node 22 is available.

## Review Focus

- A replay JSON with `clock: []`, a string clock value, or a settings call missing arguments must be rejected with zero engine calls.
- An 88-byte binary replay that declares 2 ticks but expands to 50 calls must fail before WASM init.
- A save import where storage accepts the first write then refuses restores must say so, not "Nothing was changed".
- An oversized `File` must be rejected before `file.text()` / `arrayBuffer()` is called.
- Pausing, switching the active profile, then pressing Retry must relaunch the captured pilot and loadout.
